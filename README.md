# ТАКТ — диспетчерская для городского трамвая

Демонстрационный проект: продуктовый лендинг плюс работающий интерфейс диспетчерской
трамвайного оператора. Схема сети живая — по ней едут 47 вагонов, смену можно
перемотать вперёд и назад, происшествия связаны с движением, а не нарисованы отдельно.

Учебная работа. Компания «ТАКТ», внедрение в Лодзи, сотрудники, цифры и события
вымышлены. Названия улиц, депо и районов Лодзи настоящие — события в них нет.

---

## Как запустить

Никакой сборки не требуется. Открыть `index.html` двойным кликом — сайт полностью
работает с `file://`, включая шрифты и симулятор.

Если удобнее локальный сервер (например, чтобы проверить заголовки безопасности):

```bash
python -m http.server 8080
```

Сборки production-версии нет: то, что лежит в папке, и есть production-версия.
Файлы `.env.example` и настройки хостинга ниже нужны на момент, когда к форме
заявки подключат серверную часть.

## Три языка

Русский, польский и английский. Переключатель в шапке, выбор запоминается,
`<html lang>` меняется вместе с текстом, у страниц проставлены `hreflang`.
Язык берётся по порядку: `?lang=` в адресе → сохранённый выбор → язык браузера
→ русский. Внутренние ссылки достраиваются параметром, поэтому при переходе
на другую страницу язык не слетает.

Переключение мгновенное, без перезагрузки: разметка размечена ключами
`data-i18n`, тексты живут в словарях `assets/js/i18n/`. Собранные кодом части —
лента, таблица, отчёты, палитра — пересобираются по событию смены языка.

**Топонимы не переводятся, а транслитерируются.** «Пётрковска» и «Piotrkowska» —
одна и та же улица, поэтому в данных два варианта названия, кириллица и латиница,
а не три перевода: польская и английская версии показывают оригинальные польские
названия остановок, депо и фамилии водителей.

**Тексты происшествий** вынесены в отдельные файлы по идентификатору события
(`incidents-pl.js`, `incidents-en.js`): само событие — время, линия, точка на
схеме — одно на все языки, меняется только формулировка.

| Файл | Что содержит |
|---|---|
| `i18n/core.js` | движок: определение языка, подстановка, переключатель |
| `i18n/ru.js` · `pl.js` · `en.js` | публичные страницы |
| `i18n/ru-app.js` · `pl-app.js` · `en-app.js` | интерфейс диспетчерской |
| `i18n/incidents-pl.js` · `incidents-en.js` | тексты происшествий |
| `i18n/legal.js` | политика конфиденциальности на трёх языках |

Терминология подобрана отраслевая, а не дословная: выход → brygada → run,
депо → zajezdnia → depot, контактная сеть → sieć trakcyjna → overhead line,
интервал → interwał → headway.

## Откуда взялась схема сети

**Настоящую топологию путей Лодзи я не брал — схема нарисована с нуля.**
Из реального в ней только имена: районы и улицы (Пётрковска, Манифактура,
Рынек Балуцкий, Хойны, Стоки, Ретькиня, Теофилув), названия трёх депо
(Хойны, Телефоничная, Брус) и номера маршрутов, которые в Лодзи существуют.
Трассы, порядок остановок, пересадочные узлы, длины и интервалы — вымышлены
и подобраны так, чтобы схема читалась и по ней было интересно вести смену.

Совпадение одно и намеренное: линия 8 «Згеж — Пабянице» действительно самая
длинная в городе и действительно связывает два пригорода через центр. Её длина
в данных — 32,4 км — близка к реальной, остальные цифры к натуре не привязаны.

Поэтому на карте стоит подпись «Схема, а не географическая карта», а внизу
лендинга — «Названия улиц и депо реальные, события — нет». В демонстрационном
проекте это честнее, чем выдавать придуманное за данные оператора.

**Если понадобится настоящая сеть**, брать её нужно из открытых источников,
а не срисовывать: геометрия путей есть в OpenStreetMap (лицензия ODbL, требует
указания источника), маршруты и расписания операторы публикуют в формате GTFS.
Загрузчик пришлось бы писать отдельно: схема метро-типа не получается из
географии автоматически — линии для неё спрямляют вручную, и делают это дизайнеры.

## Стек и решения

**Чистые HTML, CSS и JavaScript. Ноль зависимостей** — ни фреймворка, ни сборщика,
ни библиотек анимации. Морфинг путей и интерполяция здесь занимают шестьдесят строк,
а GSAP с flubber весили бы 90 КБ и требовали загрузки с CDN.

**Положение вагона — чистая функция времени:**

```
положение = график(t − отклонение(t))
```

Опаздывающий на семь минут вагон находится там, где по расписанию должен был быть
семь минут назад. Из этой строчки бесплатно следует три вещи:

- перемотка назад работает сама собой — это просто другое `t`;
- лента, графики и числа не могут разойтись между собой: у них одно `t`;
- переход с лендинга в продукт не сбивает движение — новая страница считает
  позиции от того же `t`, полученного через `sessionStorage`.

**Данные лежат в `.js`, а не в `.json`.** Требование «открывается двойным кликом»
несовместимо с `fetch()`: браузер блокирует чтение файлов с `file://`. Структура
данных при этом ровно та же. При выкладке на хостинг переключается за пару минут:
в `assets/js/data/*.js` убрать обёртку `window.TAKT.x = ...`, оставив чистый JSON,
и заменить теги `<script>` на загрузку через `fetch` в `simulator.init()`.

**Роли — это разные экраны, а не спрятанные кнопки.** У диспетчера карта,
линия, происшествия и отчёты. У начальника депо вместо схемы сводка смены
крупными числами и список незакрытых событий: он не ведёт движение, он его
контролирует. У водителя один экран с одним главным числом — отклонение от
графика размером в пол-карточки, интервал до впереди идущего и указание
диспетчера. Навигация меняется вместе с ролью: лишних экранов не существует,
а не «они скрыты в меню».

**Производительность.** Один общий `requestAnimationFrame` на все 47 вагонов;
позиции ставятся только через `transform: translate3d()`; путь сэмплируется один раз
в таблицу точек, вместо вызова `getPointAtLength()` в каждом кадре. Кадр рисует
только активный экран. Замер на этой машине: пересчёт всей сети плюс отрисовка —
**0,083 мс на кадр** при бюджете 16,7 мс — запас примерно в двести раз.

## Что нужно подключить при реальном запуске

Сайт статический и намеренно ничего не отправляет наружу. Чтобы он стал рабочим:

1. **Форма заявки.** Сейчас проверяет ввод и показывает честное сообщение, что
   отправлять некуда. Нужен обработчик: почтовый сервис, CRM или serverless-функция.
   Переменные — в `.env.example`. Обязательно добавить **серверную** валидацию:
   клиентская защищает только от опечаток.
2. **Защита формы от спама.** В разметке уже есть honeypot-поле `company_url`;
   к нему нужны rate limiting по IP и капча.
3. **Авторизация.** Кнопка «Войти» ведёт в демо. Настоящий вход, роли и права
   проверяются на сервере — переключатель роли в демо это витрина, а не система прав.
4. **Экспорт отчётов в PDF** — заглушка, честно об этом сообщающая.
5. **Источники данных диспетчерской**: GPS-трекеры, турникеты, датчики контактной сети.
   Сейчас их заменяет детерминированный симулятор.

Секретов в коде нет и быть не может: хранить их негде. Ключи живут в панели хостинга.

## Безопасность

Что сделано:

- CSP через `<meta>` на каждой странице: `default-src 'self'`, внешние запросы запрещены;
- ни одного обращения наружу — шрифты локальные, аналитики и трекеров нет;
- пользовательские данные вставляются только через `textContent`, `innerHTML`
  с ними не используется — форма не может стать вектором XSS;
- `Referrer-Policy`, `X-Content-Type-Options` (через конфиг хостинга ниже);
- honeypot в форме, `novalidate` + собственная валидация с понятными сообщениями.

Что нужно настроить на хостинге:

```
# заголовки для статического хостинга
Content-Security-Policy: default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self'; font-src 'self'; connect-src 'self'; base-uri 'none'; frame-ancestors 'none'
Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: geolocation=(), microphone=(), camera=(), payment=()
```

Что остаётся риском и требует внимания после запуска:

- HTTPS обязателен: без него CSP и HSTS не имеют смысла;
- зависимостей нет, но при добавлении любой библиотеки нужен регулярный аудит;
- резервное копирование настраивается на стороне хостинга;
- утверждать, что сайт «невозможно взломать», нельзя ни про один сайт.

## Доступность

- контраст проверен для **30 пар цветов в обеих темах** — все проходят WCAG 2.2 AA
  (текст 4.5:1, границы полей и кнопок 3:1);
- статус вагона передаётся **формой значка и подписью**, а не только цветом:
  круг — в графике, круг с сектором — опаздывает, кольцо — опережает, квадрат — стоит,
  треугольник — авария. Интерфейс читается в чёрно-белом скриншоте и при дейтеранопии;
- полное управление с клавиатуры: Tab по вагонам, стрелки по времени, `Ctrl+K` —
  командная палитра, пробел — пауза, `1`–`4` — экраны, `Esc` закрывает панели;
- `prefers-reduced-motion`: вагоны обновляют позицию скачком раз в секунду,
  постановочные переходы отключаются, **вся функциональность сохраняется**;
- новое происшествие объявляется через `aria-live="polite"`, авария — `assertive`;
  числа в шапке намеренно не озвучиваются: они меняются постоянно.

## Ограничения заказчика, по которым проверялась работа

- ничего не пульсирует постоянно — импульс допустим один раз, в момент события;
- **красный цвет только на авариях**: проверяется `grep -rn "C4342B"` — он встречается
  лишь в объявлении токена, а `var(--st-alarm)` используется исключительно в статусах
  происшествий. Ошибки формы поэтому янтарные, а не красные;
- обновление данных не сдвигает строку под курсором: лента пересобирается только
  при изменении состава событий, в остальное время меняется один текстовый узел;
- все числа набраны `Martian Mono` с `font-variant-numeric: tabular-nums` —
  ширина колонок не дёргается;
- служебные переходы 120–200 мс; медленных ровно три и они постановочные:
  распрямление линии (700 мс), скраббинг и переход с лендинга.

с чужого процессора в портфолио не годятся.

## Развёртывание

Любой статический хостинг: GitHub Pages, Netlify, Cloudflare Pages, обычный nginx.
Залить папку целиком, настроить заголовки из раздела «Безопасность», указать
`404.html` как страницу ошибки. Перед публикацией заменить `takt.example`
в `canonical`, `og:*`, `robots.txt` и `sitemap.xml` на настоящий домен.
